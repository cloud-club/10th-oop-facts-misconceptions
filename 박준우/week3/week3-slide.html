오늘의 한 문장: 객체를 결정하는 것은 데이터가 아니라 행동입니다.

오늘은 3장의 핵심 질문인 “타입이란 무엇인가”를 다룹니다. 책은 타입을 추상화라고 정의하고, 타입을 결정하는 것은 데이터가 아니라 행동이라고 말합니다. 이 두 가지를 C++ 코드 예시 세 개로 확인해 보겠습니다. 시간 배분은 화면과 같습니다. (약 30초)

추상화란?

복잡도를 극복하는 방법

어떤 대상을 명확하게 이해하기 위해, 세부 사항이나 구조를 의도적으로 생략하거나 감추는 것입니다.

1차원: 일반화

구체적인 사물들의 공통점은 취하고 차이점은 버립니다.

스마트폰, 노트북, 스마트워치 → 기기

2차원: 불필요한 세부 사항 제거

중요한 부분을 강조하기 위해 지금 목적에 필요 없는 것을 걷어냅니다.

충전소 관리라면 와이파이는 필요 없음

무엇이 공통이고 무엇이 불필요한지 판단하는 기준은 필드가 아니라 객체의 행동입니다.
두 차원 모두 “무엇을 버릴 것인가”를 정하는 일입니다. 1차원은 대상들 사이의 차이를 버리는 것이고, 2차원은 지금 목적에 필요 없는 것을 버리는 것입니다. 그리고 이때 판단 기준은 필드가 아니라 행동입니다. 객체가 어떤 행동을 하는지를 보고 공통점을 찾고, 프로그램의 목적에 필요한 행동만 남기며, 데이터는 그 행동을 따라 남습니다. 이 순서를 전자 기기 예시로 따라가 보겠습니다. (약 1분)

문제: 같은 행동이 세 번 반복되고, 셋이 모두 “기기”라는 하나의 개념이라는 사실이 코드에 드러나지 않습니다.
먼저 추상화를 적용하기 전입니다. 스마트폰, 노트북, 스마트워치를 각각 클래스로 만들었습니다. 파란색 줄은 세 기기가 모두 하는 공통 행동이고, 노란색 줄은 기기마다 다른 고유 행동입니다. 보시다시피 같은 여섯 줄이 세 번 반복됩니다. 그리고 이 셋이 모두 “기기”라는 사실은 코드 어디에도 드러나지 않습니다. (약 1분)

Step 1. 1차원: 차이는 버리고 공통 행동만 취한다

예시 1

버리는 것: 고유 행동

openLid() 노트북만
measureHeartRate() 스마트워치만

취하는 것: 공통 행동

클래스 세 개가 Device 하나로 줄었습니다.

Device — 기기라면 누구나 하는 행동의 집합
class Device {
public:
@c   void plugIn();
@c   void unplug();
@c   int  batteryLevel() const;
@c   void connectWifi(const std::string& ssid);
@c   void disconnectWifi();
@c   bool isConnected() const;
private:
  // 행동을 수행하는 데 필요한 상태:
  // charging, battery, ssid ...
};
그러나 충전 행동과 네트워크 행동이 한 타입에 섞여 있어, 어떤 프로그램도 이 모두를 필요로 하지는 않습니다.
1차원을 적용합니다. 기기마다 다른 행동인 통화, 덮개 열기, 심박 측정은 버립니다. 그리고 세 기기가 모두 하는 행동만 모아 Device 하나로 묶습니다. 클래스가 세 개에서 하나로 줄었고, 이제 코드에 “기기”라는 개념이 드러납니다. 다만 이 Device에는 충전과 네트워크라는 두 종류의 행동이 섞여 있습니다. 실제 프로그램은 대부분 이 둘을 모두 필요로 하지 않습니다. (약 1분)

Step 2. 2차원: 목적에 불필요한 행동을 제거한다

예시 1
목적 A: 충전소 관리 프로그램
Device
class Device {
public:
@a   void plugIn()  { charging_ = true; }
@a   void unplug()  { charging_ = false; }
@a   int  batteryLevel() const { return battery_; }
@x   void connectWifi(const std::string& ssid);
@x   void disconnectWifi();
@x   bool isConnected() const;
private:
@a   bool charging_ = false;
@a   int  battery_ = 0;
@x   std::string ssid_;
};
목적 B: 사무실 네트워크 관리 프로그램
Device
class Device {
public:
@x   void plugIn();
@x   void unplug();
@x   int  batteryLevel() const;
@b   void connectWifi(const std::string& s) { ssid_ = s; }
@b   void disconnectWifi()    { ssid_.clear(); }
@b   bool isConnected() const { return !ssid_.empty(); }
private:
@x   bool charging_ = false;
@x   int  battery_ = 0;
@b   std::string ssid_;
};
행동을 정하자 필요한 상태가 따라서 남았습니다. 필드는 한 번도 직접 고르지 않았습니다.
2차원을 적용합니다. 같은 Device라도 프로그램의 목적에 따라 필요한 행동이 다릅니다. 충전소 관리 프로그램은 꽂고, 빼고, 배터리 잔량을 보는 행동만 필요합니다. 그래서 와이파이 행동을 제거했더니, 접속 중인 SSID라는 상태도 함께 사라졌습니다. 반대로 네트워크 관리 프로그램은 접속 행동만 필요하고, 충전 여부와 배터리 잔량 상태가 함께 사라집니다. 여기서 주목하실 점은 제가 필드를 직접 고른 적이 없다는 것입니다. 행동을 정하자 상태가 따라왔습니다. 책의 표현으로는 상태는 행동의 부산물입니다. (약 1분 30초)

개념을 보는 세 가지 관점

책의 예: 앨리스의 트럼프
관점의미책 속 예시 (트럼프)C++에서는
심볼개념을 가리키는 간략한 이름“트럼프”class Device
내연개념의 완전한 정의, 객체가 속하는지 판단하는 조건몸이 납작하고 두 손과 두 발이 네모난 몸 모서리에 달려 있다공개 인터페이스(행동)와 지켜야 할 규칙
외연개념에 속하는 모든 객체의 집합정원사, 병사, 신하, 하트 잭, 하트 왕, 하트 여왕Device로 만든 인스턴스들
내연은 현실 세계의 설명이므로, 코드에서 그대로 필드로 만들 필요는 없습니다. 코드에서는 “이 타입이 무엇을 할 수 있는가”가 내연의 역할을 합니다.
책은 개념을 세 가지 관점으로 설명합니다. 심볼은 이름이고, 내연은 개념의 정의이며, 외연은 그 개념에 속하는 객체들의 집합입니다. 책에서는 앨리스 이야기의 트럼프로 설명하지만, 코드 예시는 기기로 보여드렸습니다. 한 가지 짚을 점은 내연입니다. “몸이 납작하다” 같은 설명은 현실 세계의 서술이지, 코드의 필드로 옮길 대상이 아닙니다. 코드에서는 타입이 제공하는 행동과 규칙이 내연의 역할을 합니다. (약 1분)

타입은 행동입니다

타입 = 개념

데이터 타입

  • 타입은 데이터가 어떻게 사용되느냐에 관한 것입니다.
  • 정수는 + - * /, 문자열은 길이 구하기처럼 적용 가능한 연산이 타입을 결정합니다.
  • 메모리에 어떻게 표현하는지는 외부로부터 감춰집니다.

객체의 타입도 마찬가지

  • 객체는 행동이 중심이고, 상태는 행동의 부산물입니다.
  • 동일한 행동을 하면 내부 표현이 달라도 같은 타입입니다.
  • 내부 표현을 감추는 것이 캡슐화, 같은 메시지를 다르게 처리하는 것이 다형성입니다.
“객체를 결정하는 것은 행동이다. 데이터는 단지 행동을 따를 뿐이다.”
타입은 개념과 같고, 타입의 인스턴스는 그 타입을 구성하는 객체 집합의 일원입니다. 책은 데이터 타입에서 두 가지를 짚습니다. 하나는 타입이 그 데이터에 적용할 수 있는 연산으로 결정된다는 것이고, 다른 하나는 메모리 표현이 외부로부터 감춰진다는 것입니다. 이 두 가지는 객체의 타입에도 그대로 적용됩니다. 그래서 예시 1에서 처음부터 끝까지 행동을 기준으로 추상화했던 것입니다. 다음 예시로 이를 확인해 보겠습니다. (약 1분)

예시 2. 행동이 같으면 같은 타입입니다

예시 2 · 좌표
타입 = 행동의 집합 (데이터 없음)
class Point {
public:
  virtual ~Point() = default;
  virtual double x() const = 0;
  virtual double y() const = 0;
  double distanceFromOrigin() const {
    return std::sqrt(x()*x() + y()*y());
  }
};
내부 표현 1: 직교좌표 (x, y)
class CartesianPoint : public Point {
public:
  CartesianPoint(double x, double y) : x_(x), y_(y) {}
  double x() const override { return x_; }
  double y() const override { return y_; }
private:
  double x_, y_;
};
내부 표현 2: 극좌표 (r, θ)
class PolarPoint : public Point {
public:
  PolarPoint(double r, double t) : r_(r), t_(t) {}
  double x() const override { return r_ * std::cos(t_); }
  double y() const override { return r_ * std::sin(t_); }
private:
  double r_, t_;
};
사용하는 쪽은 내부 표현을 모릅니다
void printDistance(const Point& p) {
  std::cout << p.distanceFromOrigin() << '\n';
}
int main() {
  CartesianPoint a(3.0, 4.0);
  PolarPoint     b(5.0, std::atan2(4.0, 3.0));
  printDistance(a);   // 5
  printDistance(b);   // 5
}
같은 타입데이터가 전혀 달라도 행동이 같으므로 둘 다 Point입니다.
캡슐화printDistance는 내부 표현을 모릅니다.
다형성같은 메시지 x(), y()를 다른 방식으로 처리합니다.
직교좌표는 x, y를 저장하고 극좌표는 반지름과 각도를 저장합니다. 내부 데이터가 완전히 다릅니다. 그런데 x()와 y()라는 행동은 똑같이 제공합니다. 그래서 둘 다 Point 타입입니다. 맨 위 Point 클래스를 보시면 데이터가 하나도 없는 순수한 행동의 명세인데도 타입으로 성립합니다. 이것이 “타입은 행동이다”라는 말을 가장 잘 보여줍니다. printDistance는 내부 표현을 모르기 때문에, 나중에 표현을 바꿔도 수정할 필요가 없습니다. 이것이 캡슐화이고, 같은 메시지를 다르게 처리하는 것이 다형성입니다. (약 3분)

서브타입 (특수한 타입)일반적인 타입의 모든 행동을 포함하고, 자신만의 행동을 추가한 타입입니다.
“일반화/특수화는 행동에 관한 것이다.”
책에서는 트럼프가 트럼프 인간보다 일반적인 개념이고, 트럼프 인간이 더 특수한 개념이라고 설명합니다. 이 관계를 일반화와 특수화라고 합니다. 중요한 것은 이 관계가 행동의 관점이라는 점입니다. 일반적인 타입은 특수한 타입이 가진 행동 중 일부만 가진 타입입니다. 특수한 타입은 일반적인 타입의 모든 행동을 포함하고, 거기에 자기만의 행동을 더한 타입입니다. 화면의 기기와 스마트워치로 보면 Device는 충전 행동만 갖고, SmartWatch는 그 행동을 모두 갖고 심박 측정을 추가합니다. (약 1분)

예시 3. 슈퍼타입과 서브타입

예시 3 · 기기와 스마트워치
슈퍼타입은 일부만, 서브타입은 모두 + 추가
class Device {              // 슈퍼타입
public:
  void plugIn()  { charging_ = true; }
  void unplug()  { charging_ = false; }
  int  batteryLevel() const { return battery_; }
private:
  bool charging_ = false;
  int  battery_ = 0;
};

class SmartWatch : public Device {   // 서브타입
public:
  int measureHeartRate() const { return 72; }
};

void startCharging(Device& d) { d.plugIn(); }

int main() {
  Device     phone;
  SmartWatch watch;
  startCharging(phone);   // 가능
  startCharging(watch);   // 가능: 모든 행동을 가짐
  watch.measureHeartRate();
  // phone.measureHeartRate();   // 컴파일 오류
}
대체할 수 있습니다SmartWatch는 Device의 모든 행동을 가지므로 Device가 필요한 곳 어디에나 쓸 수 있습니다.
반대는 안 됩니다Device에는 measureHeartRate()가 없으므로 서브타입이 필요한 곳에 쓸 수 없습니다.
예시 1과 이어집니다Device는 목적 A(충전소 관리)에서 만든 타입입니다.
예시 3은 예시 1에서 만든 Device를 그대로 이어서 씁니다. Device는 충전소 관리 목적으로 추상화한 타입이고, 충전 행동 세 개만 갖습니다. SmartWatch는 Device를 상속받아 심박 측정이라는 자기만의 행동을 추가합니다. startCharging 함수는 Device의 행동만 요구하기 때문에 SmartWatch를 넘겨도 문제없습니다. 서브타입은 슈퍼타입의 행동을 모두 갖고 있기 때문입니다. 반대로 phone에서 measureHeartRate를 호출하면 컴파일 오류가 납니다. 상속을 데이터나 코드 재사용이 아니라 행동의 포함 관계로 봐야 한다는 점이 이 장의 핵심입니다. (약 3분)

정적 모델과 동적 모델

결국 타입은 추상화다

타입은 시간과 상태 변화라는 요소를 제거하고, 대상을 정적인 관점에서 보게 해 줍니다.

동적 모델정적 모델
표현하는 것특정 시점의 객체 상태, 즉 스냅샷객체가 가질 수 있는 모든 상태와 행동
시간시간에 따라 변함시간에 독립적

예시 3에서는main()에서 만든 phone, watch의 한 시점 상태class Device, class SmartWatch 선언 자체
마지막 개념입니다. 객체를 모델링하는 방법은 두 가지입니다. 동적 모델은 객체가 특정 시점에 어떤 상태를 갖는지, 즉 스냅샷을 포착합니다. 정적 모델은 객체가 가질 수 있는 모든 상태와 행동을 시간과 무관하게 표현합니다. 클래스 선언이 바로 정적 모델입니다. 시간이라는 요소를 제거했다는 점에서 타입은 추상화입니다. (약 1분)

정리

1분
  1. 추상화는 차이점을 버리거나(1차원) 불필요한 세부 사항을 제거하는(2차원) 일이며, 무엇이 불필요한지는 목적이 정합니다.
  2. 개념은 심볼·내연·외연으로 설명하고, 객체를 분류한다는 것은 개념을 적용하는 일입니다.
  3. 타입은 행동으로 결정되며, 내부 표현은 감춥니다. (캡슐화, 다형성)
  4. 슈퍼타입과 서브타입의 관계는 행동의 포함 관계입니다.
  5. 타입은 시간을 제거한 정적 모델이며, 결국 타입은 추상화입니다.
클래스를 설계할 때 “무슨 필드를 가질까”보다 “이 프로그램의 목적에서 어떤 행동이 필요할까”를 먼저 물어보시길 권합니다.
정리하겠습니다. 추상화는 무엇을 버릴지 정하는 일이고, 그 기준은 목적과 행동입니다. 타입은 데이터가 아니라 행동으로 결정되며, 슈퍼타입과 서브타입은 행동의 포함 관계입니다. 마지막으로 하나만 기억해 주신다면, 클래스를 설계할 때 “무슨 필드를 가질까”보다 “이 프로그램의 목적에서 어떤 행동이 필요할까”를 먼저 물어보시길 권합니다. 감사합니다. (약 1분)
