# Week 3. 타입과 추상화

## 1. 기억에 남은 내용

3장에서 가장 기억에 남은 건 객체를 결정하는 것은 행동이고, 데이터는 그 행동을 따를 뿐이라는 내용입니다.

2장에서는 행동이 상태를 결정한다고 했는데, 3장은 한 걸음 더 나아가 행동이 타입까지 결정한다고 말합니다.
객체를 분류할 때도 어떤 데이터를 가졌는지가 아니라 어떤 행동을 하는지를 봐야 한다는 점이 인상 깊었습니다.

## 2. 3장의 흐름

3장은 앞의 개념이 다음 개념의 바탕이 되는 구조라서, 흐름으로 정리해 봤습니다.

```text
추상화: 목적에 맞게 불필요한 것을 버린다
  → 개념: 공통점으로 객체를 묶는다
    → 타입: 개념을 프로그래밍으로 옮긴 것. 행동으로 결정된다
      → 타입 계층: 일반화와 특수화. 서브타입은 슈퍼타입을 대체할 수 있어야 한다
        → 정적 모델: 시간에 따라 변하는 상태를 단순하게 본다
          → 클래스: 타입을 구현하는 방법 중 하나
```

### 추상화: 목적에 맞게 버리기

장은 해리 벡의 런던 지하철 노선도로 시작합니다.
초기 노선도는 실제 지형과 거리를 사실적으로 그려서 오히려 보기 어려웠습니다.
해리 벡은 지형과 축척을 버리고 역의 순서와 환승역만 남겼고, 이 방식은 지금까지 전 세계 노선도의 바탕이 됐습니다.

승객에게 필요한 건 역의 정확한 위치가 아니라 어디서 타고 어디서 갈아타는지였습니다.
그래서 책은 좋은 추상화란 목적에 맞는 추상화라고 말합니다.
반대로 이 노선도는 실제 거리를 알고 싶은 사람에게는 맞지 않습니다. 같은 추상화도 다른 목적으로 쓰면 오히려 헷갈리게 만들 수 있습니다.

책은 추상화를 두 가지 차원으로 설명합니다.
- 공통점은 취하고 차이점은 버리는 일반화
- 중요한 부분을 강조하기 위해 불필요한 세부 사항을 제거하는 것

### 개념: 공통점으로 묶기

정원에 들어선 앨리스는 정원사, 병사, 신하, 왕과 여왕을 보고 기껏해야 트럼프라고 생각합니다.
계급이나 성격 같은 차이는 무시하고, 몸이 납작하고 네모난 모서리에 팔다리가 달렸다는 공통점만 본 것입니다.

이렇게 공통점을 기준으로 객체를 묶는 틀을 개념이라고 합니다.
개념을 적용할 수 있는 객체를 그 개념의 인스턴스라고 하고, 개념에 따라 객체를 나누는 일을 분류라고 합니다.

책은 개념을 세 가지 관점으로 설명합니다.

| 관점 | 의미 | 트럼프 예시 |
| --- | --- | --- |
| 심볼 | 개념을 가리키는 이름 | 트럼프 |
| 내연 | 개념의 정의. 객체가 개념에 속하는지 판단하는 조건 | 몸이 납작하고 네모 귀퉁이에 팔다리가 달린 등장인물 |
| 외연 | 개념에 속하는 객체들의 집합 | 정원사, 병사, 신하, 왕과 여왕 등 |

책은 이 세 가지 용어보다 개념으로 객체를 분류할 수 있다는 사실이 더 중요하다고 강조합니다.
그리고 어떤 객체를 어떤 개념으로 분류하느냐가 설계의 품질을 결정한다고 말합니다.

### 타입: 행동으로 결정된다

타입은 개념과 같은 뜻입니다. 공통점으로 객체를 묶는 틀을 컴퓨터 공학에서 부르는 이름입니다.

메모리 안에는 0과 1만 있어서, 그 값이 숫자인지 문자인지 알 수 없습니다.
그래서 사람들은 데이터를 어떻게 쓰는지에 따라 분류하기 시작했고, 여기서 타입 시스템이 생겼습니다.

책은 데이터 타입에서 두 가지 사실을 이끌어 냅니다.
- 데이터에 어떤 연산을 적용할 수 있는지가 타입을 결정한다.
- 데이터가 메모리에 어떻게 표현되는지는 외부에 감춰진다.

이 두 가지는 객체에도 그대로 적용됩니다.
- 객체가 어떤 행동을 하는지가 타입을 결정한다.
- 객체의 내부 표현은 외부에 감춰진다.

그래서 같은 데이터를 가졌더라도 행동이 다르면 다른 타입이고, 내부 표현이 달라도 같은 행동을 하면 같은 타입입니다.
여기서 다형성과 캡슐화가 자연스럽게 나옵니다.
같은 타입의 객체들은 같은 메시지를 받지만 내부 표현이 다르기 때문에 서로 다른 방식으로 처리할 수 있고, 행동만 보면 되기 때문에 데이터는 행동 뒤로 감춰야 합니다.

### 타입 계층: 일반화와 특수화

앨리스가 본 등장인물들은 사실 트럼프 카드가 아니라 트럼프 인간입니다.
트럼프 카드는 엎드리고 뒤집어질 수 있지만, 걸어 다니지는 못하기 때문입니다.

트럼프 인간은 트럼프가 하는 행동을 모두 하면서 걷기까지 할 수 있습니다.
이때 트럼프는 더 일반적인 타입이고, 트럼프 인간은 더 특수한 타입입니다.

재미있는 점은 행동의 수와 집합의 크기가 반대라는 것입니다.

| 구분 | 행동의 수 | 속하는 객체의 수 |
| --- | --- | --- |
| 일반적인 타입 (트럼프) | 적음 | 많음 |
| 특수한 타입 (트럼프 인간) | 많음 | 적음 |

일반적인 타입을 슈퍼타입, 특수한 타입을 서브타입이라고 합니다.
서브타입이 되려면 슈퍼타입의 행동과 호환되어야 하고, 슈퍼타입을 대신할 수 있어야 합니다.

### 정적 모델: 시간을 지우고 보기

앨리스의 키는 무엇을 먹고 마시느냐에 따라 계속 바뀝니다.
그때마다 가능한 키를 모두 떠올리는 대신, 앨리스는 변할 수 있는 키라는 상태를 가진다고 생각하면 훨씬 단순해집니다.

이렇게 시간에 따라 변하는 상태를 시간과 무관하게 보게 해 주는 것이 타입입니다. 그래서 타입도 추상화입니다.

책은 객체를 볼 때 두 가지 모델을 함께 고려한다고 말합니다.

| 모델 | 무엇을 보는가 | 프로그래밍에서는 |
| --- | --- | --- |
| 동적 모델 | 특정 시점에 객체가 어떤 상태인지 | 실행하면서 디버깅할 때 |
| 정적 모델 | 객체가 가질 수 있는 모든 상태와 행동 | 클래스를 작성할 때 |

### 클래스는 타입이 아니다

객체지향 언어에서는 보통 클래스로 타입을 구현합니다.
하지만 클래스는 타입을 구현하는 여러 방법 중 하나일 뿐입니다. 자바스크립트 같은 프로토타입 기반 언어에는 클래스가 없습니다.

클래스는 코드를 재사용하는 데도 쓰이기 때문에, 클래스와 타입을 같은 것으로 보면 혼란이 생길 수 있다고 책은 말합니다.

## 3. 코드로 옮겨 보기

트럼프 예시를 코드로 옮기면 다음과 같습니다. 책 내용을 이해하기 위해 만든 예시입니다.

```java
interface Trump {
    void lieFlat();
    void flip();
}

interface TrumpHuman extends Trump {
    void walk();
}
```

- `Trump`와 `TrumpHuman`은 필드 없이 행동만으로 정의됩니다. 행동이 타입을 결정한다는 내용과 이어집니다.
- `TrumpHuman`은 `Trump`의 행동을 모두 가지면서 `walk()`를 추가합니다. 트럼프 인간이 트럼프의 서브타입이라는 관계입니다.
- 클래스가 아니라 인터페이스로도 타입을 표현할 수 있습니다. 클래스와 타입이 다르다는 내용과 이어집니다.

`Trump`를 기대하는 곳에는 `TrumpHuman`을 넣어도 문제없이 동작해야 합니다. 서브타입이 슈퍼타입을 대체할 수 있어야 한다는 말이 이런 뜻입니다.

## 4. 1, 2장과 이어지는 부분

| 앞 장 | 3장 |
| --- | --- |
| 1장: 클래스는 객체지향의 도시전설이다 | 클래스는 타입을 구현하는 방법 중 하나일 뿐이다 |
| 1장: 같은 요청에 다르게 응답하는 다형성 | 같은 타입이지만 내부 표현이 달라 다르게 처리한다 |
| 2장: 행동이 상태를 결정한다 | 행동이 타입을 결정한다 |
| 2장: 상태를 행동 뒤로 캡슐화한다 | 데이터를 행동 뒤로 감춰야 행동으로 분류할 수 있다 |

3장을 읽으면서 1, 2장에서 나온 이야기들이 결국 하나의 생각으로 모인다고 느꼈습니다.
"행동이 우선이다"라는 3장의 소제목이 그 생각을 가장 잘 요약하는 것 같습니다.
