# Week 2. 1, 2장을 읽고

## 1. 책을 읽고

백엔드 개발을 하면서 좋은 객체지향 설계가 뭘까 고민하다 이 스터디를 열었는데, 1장부터 제가 알던 설명과 달라서 재미있었습니다.

저도 객체지향은 현실 세계를 코드로 옮기는 것이라고 배웠습니다.
그런데 책은 이 설명이 입문할 때는 도움이 되지만 실제 설계에는 잘 맞지 않는다고 말합니다(p.21~22).
클래스 이야기도 비슷합니다. 객체지향 하면 클래스와 상속이 먼저 떠오르는데, 책은 클래스를 협력 관계를 코드로 옮기는 도구로 봅니다(p.38).
중요한 건 어떤 객체들이 어떤 메시지를 주고받는지라는 내용을 읽고, 그동안 무엇을 먼저 보고 있었는지 돌아보게 됐습니다.

2장에서 가장 기억에 남은 문장은 "행동이 상태를 결정한다"(p.66)입니다.
객체를 만들 때는 어떤 필드가 필요한지부터 떠올리기 쉬운데, 책은 협력에 필요한 행동을 먼저 생각하라고 합니다.
순서만 바뀐 것처럼 보이지만, 상태부터 정하면 캡슐화가 깨지기 쉽고 협력에 맞지 않는 객체가 만들어질 수 있다는 설명이 와닿았습니다(p.64~65).

앨리스 이야기도 처음에는 왜 나오나 싶었는데, 음료 부분에서 이해가 됐습니다.
현실의 음료는 스스로 양을 줄이지 못하지만, 코드 속 음료는 자기 양을 직접 관리합니다(p.55).
현실을 그대로 따라 하는 게 아니라 새로운 세계를 만든다는 말이 이런 뜻이구나 싶었습니다.

## 2. 코드로 다시 보기

읽다 보니 멀티모듈을 공부해 보려고 만들었던 투두 앱 서버, [BBANGZIP](https://github.com/Team-BBANGZIP/BBANGZIP-SERVER)이 떠올라서 코드를 다시 열어 봤습니다.
그중 책 내용과 이어지는 코드 두 개만 가져왔습니다.

### 자기 상태를 직접 관리하기

`CategoryEntity`는 중지 상태가 바뀔 때 중지 시각도 함께 관리합니다.

```java
if (newIsStopped) {
    if (!this.isStopped) {
        this.stoppedDate = LocalDateTime.now();
    }
} else {
    this.stoppedDate = null;
}
this.isStopped = newIsStopped;
```

호출하는 쪽에서 `stoppedDate`를 따로 계산하지 않아도 됩니다.
객체가 자기 상태를 직접 관리한다는 내용(p.33, p.52)과 이어지는 부분입니다.

### 같은 역할을 수행하기

공통 모듈에는 `ErrorCode` 인터페이스가 있고, Todo, Category, User 같은 영역이 각자 이를 구현합니다.

```java
public interface ErrorCode extends ApiCode { }

public enum TodoCoreErrorCode implements ErrorCode {
    TODO_NOT_FOUND(HttpStatus.NOT_FOUND, 40406, "투두를 찾을 수 없습니다.");
}
```

여러 객체가 같은 역할을 수행할 수 있다는 내용(p.30)을 코드로 보면 이런 모습입니다.
공통 모듈은 Todo를 몰라도 되고, 새 도메인의 에러 코드는 해당 도메인에 추가하면 됩니다.

## 3. 멀티모듈로 넓혀 보기

책은 모듈을 직접 다루지 않습니다. 다만 객체의 역할과 책임을 공부할 때 멀티모듈도 함께 살펴보면 좋겠다고 생각했습니다.
무엇을 책임지고 어디까지 알아야 하는가라는 질문을 모듈에도 똑같이 던져 볼 수 있기 때문입니다. 이 부분은 제 해석입니다.

책의 카페로 비유하면 멀티모듈은 같은 건물 안에 방을 나누고 출입 권한을 정해 둔 구조입니다.
코드에서는 사용한다고 선언한 모듈의 코드만 쓸 수 있습니다.

| 객체에서 하는 고민 | 모듈에서 하는 고민 |
| --- | --- |
| 이 객체의 책임은 무엇인가? (p.30) | 이 모듈의 책임은 무엇인가? |
| 어떻게 하는지까지 알아야 하는가? (p.33) | 다른 모듈의 내부까지 알아야 하는가? |
| 혼자 다 하는 객체가 있는가? (p.31~32) | 뭐든 들어가는 모듈이 있는가? |

자세한 설명은 [멀티모듈 정리](./week2-multi-module.md)에 따로 적었습니다.
