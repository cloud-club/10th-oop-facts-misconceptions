## 책임감 분산 (diffusion of responsibility)

사건에 대한 목격자가 많으면 많을수록 개인이 느끼는 책임감은 적어진다 

- **상황**: 대학 강의 마무리 시간에 교수님께서 질문 3개를 받고 나서 수업을 끝내준다는 상황
- **인원**: 학생 100명 (**타인의 책임 ↑**) vs 학생 5명 (**자신의 책임 ↑**)

> 명확한 책임과 역할을 지닌 참가자들이 협력에 참여해야 한다.

## 책임 (Responsibility)

- 맡아서 해야 할 임무나 의무
- 요청을 처리하기 위해 객체가 수행하는 행동

요청을 처리하기 위한 객채의 행동은 객체의 임무이자 의무이다.

### 자율적인 책임

책임만 완수할 수 있다면 나머지 구체적인 방법이나 절차는 객체가 자유롭게 선택하도록 허용한다 - **캡슐화**

```bash
                 **캡슐화**
             ┌─ 핸드 드립 ─┐
커피 주문 →  ─┤            ├ → 제조된 커피
             └─ 커피 머신 ─┘
```

### 추상적인 책임

책임은 협력에 참여하는 의도를 명확하게 설명할 수 있는 수준 안에서 추상적이어야 한다

```bash
커피 주세요
├──→ 에소프레소?
├──→ 아메리카노?
├──→ 카페라떼?
├──→ 콜드브루?
└──→ 아인슈페너?
```

우리가 말할 때도 ‘아’ (증언하라) 다르고 ‘어’ (설명하라) 다르듯이 책임을 할당할 땐 헷갈리지 않도록 충분한 맥락 설명과 적절한 단어 선택이 필요한 것 같다.

## 메시지 (Message)

- 객체의 행동을 유발하는 행위 - 메시지-전송
- 객체들이 서로 협력하기 위해 사용할 수 있는 유일한 의사소통 수단

#### 메시지(이름)와 인자

```bash
# 메시지(편지)
수신자.전송한다(내용)

# 메시지(객체)
모자장수.증언하라(어제,왕국)
```

현실 세계에서도 사람들은 다양한 수단을 통해 의사소통을 한다. 소통이 잘못되면 오해가 쌓여 안 좋은 결과를 초래할 수 있기 때문에 알맞은 소통이 필요하다. 그러나 객체지향에서는 더 정확하고 알맞은 소통(메시지)가 필요한 것 같다. 현실에서 사람은 계속 생각을 하면서 소통을 하지만 객체들은 주어진 방식(메서드)대로 행동하기 때문이다. 그렇기 때문에 메시지가 객체를 선택하게 하여 시스템이 알맞은 방식대로 굴러가게 해야한다.

### 메소드 & 다형성

**메소드:** 메시지를 처리하기 위해 내부적으로 선택하는 방법

**다형성:** 서로 다른 유형의 객체가 동일한 메시지에 대해 서로 다르게 반응하는 것(overriding)

- 대체 가능성: 객체들이 동일한 책임을 공유하여 다른 객체로 대체될 수 있다
    - 유연성
    - 확장 가능성
    - 재사용성
    - 캡슐화

**메시지 결합력 -** 객체 간 상호작용은 최소화될 수 있으며, 상호작용은 메시지 전송(message passing)이라는 한 가지 개념에 의해서만 이루어짐 → Loose Coupling

**내용 결합력 -** 한 모듈에서 다른 모듈의 내부를 직접 참조

### What/Who Cycle

객체 사이의 협력 관계를 설계하기 위해서는 먼저 ‘어떤 행위(what)’를 수행할 것인지를 결정한다는 것

- 행위를 결정하는 것은 객체 자체의 속성이 아니다
- 행위를 먼저 식별한 후에 행위를 수행할 적절한 객체를 찾는다

### 메시지를 믿어라

- 메시지를 수신하는 객체가 메시지의 의미를 이해하고 메시지를 전송한 객체가 의도한 대로 요청을 처리할 수 있는지에 대한 여부

### 인터페이스 구현의 분리

**객체 외부에 노출되는 인터페이스와 객체의 내부에 숨겨지는 구현을 명확하게 분리해서 고려해야 한다**

외부 - 인터페이스 (interface) / 내부 - 구현 (implementation)

- 객체 인터페이스 원칙 - Matt Weisfeld
    - 좀 더 추상적인 인터페이스
    - 최소 인터페이스
    - 인터페이스와 구현 간에 차이가 있다는 점을 인식

### 책임의 자율성이 협력의 품질을 결정한다.

#### 1. 자율적인 책임은 협력을 단순하게 만든다

자율적인 책임은 세부적인 사항들을 무시하고 의도를 드러내는 하나의 문장으로 표현함으로써 협력을 단순하게 만든다 - 책임이 적절하게 추상화된다.

#### 2. 자율적인 책임은 모자 장수의 외부와 내부를 명확하게 분리한다.

객체는 협력에 참여하기 위해 외부에 노출하는 부분과 책임을 수행하기 위해 내부적으로 선택하는 방법을 명확하게 나눈다 - 인터페이스와 구현의 분리

#### 3. 책임이 자율적일 경우 책임을 수행하는 내부적인 방법을 변경하더라도 외부에 영향을 미치지 않는다.

책임이 자율적일수록 변경에 의해 수정돼야 하는 범위가 좁아지고 명확해진다 - 파급효과가 객체 내부로 캡슐화되기 때문에 두 객체 간의 결합도가 낮아진다.

#### 4. 자율적인 책임은 협력의 대상을 다양하게 선택할 수 있는 유연성을 제공한다.

책임이 자율적일수록 협력이 좀 더 유연해지고 다양한 문맥에서 재활용 될 수 있다 - 설계가 유연해지고 재사용성이 높아진다.

#### 5. 객체가 수행하는 책임들이 자율적일수록 객체의 역할을 이해하기 쉬워진다.

객체를 수행하는 책임이 자율적이면 자율적일수록 객체의 존재 이유를 명확하게 표현할 수 있다 - 책임이 자율적일수록 객체의 응집도를 높은 상태로 유지하기가 쉬워진다.

> 책임이 자율적일수록 적절하게 **‘추상화’**되며, **‘응집도’**가 높아지고, **‘결합도’**가 낮아지며, **‘캡슐화’**가 증진되고, **‘인터페이스와 구현이 명확히 분리’**되며, 설계의 **‘유연성’**과 **‘재사용성’**이 향상된다.

## **같이 이야기해 보고 싶은 주제**

### 최적화

성능을 높이거나 좋은 결과를 얻기 위해 우리는 불필요한 행동 제거, 적절한 재료 선택 , 설정 값 변경 등 우리는 최적화를 하려고 한다. 이러한 최적화는 효율적인 방식으로 고착화하는 것이라고 생각한다. 고착화되는 것은 자율성을 낮추는 것인데 최적화를 위해 어디까지 자율성을 낮춰야 할 지 고려해봐야 한다.
