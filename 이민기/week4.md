## 협력 (Cooperation)

**시작** - 한 사람이 다른 사람에게 도움을 **요청**

협력은 다수의 요청과 응답으로 구성되며 전체적으로 협력은 다수의 연쇄적인 요청과 응답의 흐름으로 구성된다.

- 우리 몸 안에서도 협력이 일어나고 있다.
    
    사람이 살기 위해선 피가 돌아야한다 → 피가 돌기 위해선 산소가 필요하다 → 뇌에서 산소를 얻기 위해 호흡하라고 한다  
    

사람(동물)은 산소를 빨아들이고 이산화탄소를 내뱉는다 / 나무(광합성)는 이산화탄소를 빨아들이고 산소를 내뱉는다 - 협력 관계

- 요청과 응답은 협력에 참여하는 객체가 수행할 책임을 정의

|  | **요청** | **응답** |
| --- | --- | --- |
| **사람(동물)** | 산소 | 이산화탄소 |
| **나무** | 이산화탄소 | 산소 |


## 책임 (Responsibility)

책임은 객체의 삶과 연관있는 아주 중요한 요소라고 생각한다.

- 사람의 코가 호흡을 하지 못한다면 사람은 죽는다.
- 자동차가 굴러가지 않는다면 폐차된다.
- 휴대폰이 전화가 되지 않는다면 버려진다.
- 코드가 기능을 수행하지 않는다면 지워진다.

객체들이 책임을 다해야 객체들간의 협력이 일어난다.

## 역할 (Role)

- 어떤 객체가 수행하는 책임의 집합
- 역할은 협력 내에서 다른 객체로 대체할 수 있음을 나타내는 일종의 표식이다.
    
<img width="700" alt="image" src="https://github.com/user-attachments/assets/0e31f243-63d7-4569-b320-2421332dc4fd" />
    
- 다양한 객체들이 협력에 참여할 수 있기 때문에 협력이 좀 더 유연해지며 다양한 객체들이 동일한 협력에 참여할 수 있기 때문에 재사용성이 높아진다.

## 올바른 객체 설계

1. 견고하고 깔끔한 협력을 설계
    1. 객체들이 주고받을 요청과 응답의 흐름을 결정(ex. API 설계) → 책임
2. 책임 할당
3. 행동 결정
4. 데이터 결정
5. 클래스 결정

## 객체지향 설계 기법

- 책임-주도 설계 (Responsibility-Driven Design, RDD)
- 디자인 패턴 (Design Pattern)
- 테스트-주도 개발 (Test-Driven Development)

### 책임-주도 설계 (RDD)

**객체지향 시스템:** 역할과 책임을 수행하는 자율적인 객체들의 공동체

**객체:** 시스템의 더 큰 목표를 달성하기 위해 다른 객체와 협력하는 사회적 존재

**객체지향 시스템 목적:** 사용자의 요구를 만족시킬 수 있는 기능을 제공함과 동시에 객체들의 공동체를 구축하는 것

**객체지향 설계:** 앱의 기능을 구현하기 위한 협력 관계를 고안하고, 협력에 필요한 역할과 책임을 식별한 후 이를 수행할 수 있는 객체를 식별

**객체지향 설계 핵심:** 올바른 책임을 올바른 객체에게 할당하는 것 ⭐

**책임의 세부화:** 시스템의 책임 → 객체의 책임 → 협력자에게 책임 할당 → 협력 공동체 구축 

### 디자인 패턴 (Design Pattern)

공통으로 발생하는 문제에 대해 자주 쓰이는 설계 방법을 정리한 패턴

디자인 패턴은 패턴의 이름, 문제 및 배경, 솔루션, 사례, 결과, 샘플코드로 구성되어 있다.

디자인 패턴은 공통으로 사용할 수 있는 역할, 책임, 협력의 템플릿이며, 유사한 상황에서 반복적으로 적용할 수 있는 책임-주도 설계의 결과물이라고 할 수 있다.

### 테스트-주도 개발 (TDD)

반복 테스트를 이용한 소프트웨어 방법론으로 작은 단위의 테스트 케이스를 작성하고 이를 통과하는 코드를 추가하는 단계를 반복하여 구현한다.

#### TDD 개발 주기

<img width="600" alt="image" src="https://github.com/user-attachments/assets/21fb076f-6ab9-4976-81b3-dc1680bda559" />

- { **Red** } 단계에서는 실패하는 테스트 코드를 먼저 작성한다.
- { **Green** } 단계에서는 테스트 코드를 성공시키기 위한 실제 코드를 작성한다.
- { **Blue** } 단계에서는 중복 코드 제거, 일반화 등의 리팩토링을 수행한다.

```
테스트-주도 개발은 테스트를 작성하는 것이 아니라 책임을 수행할 객체 또는 클라이언트가 기대하는 객체의 역할이 메시지를 수신할 때
어떤 결과를 반환하고 그 과정에서 어떤 객체와 협력할 것인지에 대한 기대를 코드의 형태로 작성하는 것이다. - 136p
```

우리는 테스트를 통해 결과만 받는 것이 아니라 받은 결과를 다시 다른 곳에 전달할 수 있도록 적절한 결과가 나오기를 기대한다. 올바른 결과들이 반환되고 전달되는 프로세스를 보면서 우리는 빠르고 성능 좋고 원활한 시스템을 기대한다. 이는 객체들의 유기적인 협력을 통해 좋은 시스템을 만들 수 있으며, TDD는 유기적인 협력의 기반, 토대를 테스트 하기 위한 수단 중 하나라고 생각한다.
